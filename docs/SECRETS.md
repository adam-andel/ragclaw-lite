# Secrets & Operations Contract

This document is the **authoritative operations contract** for RAGClaw-Lite. Any operation involving secret generation, backup, recovery, or rotation follows this document as the single source of truth.
`.env.example` only describes environment variables and carries no secret contract — if you are looking for answers to questions like "how should I back up / can I replace `ragclaw_config_key`", the answer is here.

---

## 1. Overview: What secrets exist and where they live

| Secret | Storage location | In VCS? | Management |
| --- | --- | --- | --- |
| `ragclaw_config_key` (KEK) | Host file `secrets/ragclaw_config_key`, bind-mounted (read-only) into the container at `/run/secrets/ragclaw_config_key` | **No** (gitignored) | Generated by `bin/sh/lib/gen-secrets.sh`; the file may also be replaced manually |
| LLM API Key | Encrypted into `config.enc` (`/app/data/config.enc`, i.e. inside the `ragclaw_data` volume) | **No** (volume file) | **Only via the Settings page UI** |
| Embedding API Key | Same as above (same file as the LLM key) | **No** | **Only via the Settings page UI** |
| `repl_auth_secret` (REPL identity HMAC) | DB (`SystemSetting` table) | No (volume sqlite) | Auto-generated on first boot; rotated via UI "Regenerate" |
| `jwt_secret` (JWT HS256 signing) | DB (`SystemSetting` table) | No (volume sqlite) | Auto-generated on first boot; rotated via UI "Regenerate" |
| HTTPS cert / private key | Durable TLS volume (plaintext, nginx needs plaintext) | No (volume) | Uploaded via Settings; written to volume by backend |

**Key takeaway**: API Keys (LLM / Embedding) have **no `.env` or mounted-secret default source**. They come either from `config.enc` written by the Settings UI, or they are empty. On first boot (no `config.enc`) the keys are empty and must be filled in by an admin via the UI before LLM can be used.

---

## 2. ragclaw_config_key (the only mounted Docker secret)

- **What it is**: The AES-256-GCM key (KEK, Key Encryption Key) that encrypts `config.enc`.
- **Generation**: Auto-generated by `bin/sh/lib/gen-secrets.sh` on first run of `bin/sh/start.sh` into `secrets/ragclaw_config_key` (mode 600, gitignored).
- **Mounting**: docker-compose bind-mounts it read-only into the container at `/run/secrets/ragclaw_config_key`.
- **Stability**: It is a **host file**, not part of the container's writable layer, so it **does not change** after `docker compose up` rebuilds the backend container — this is precisely why the stored API Keys can survive a rebuild and still be decrypted. (The earlier scheme derived from the container MAC address, which changed on every rebuild and caused silent key loss; it is now deprecated.)
- **Hard format constraint**: Must be **64-char hex (32 bytes)**. A non-hex value is rejected at startup with a `RuntimeError`; **there is no silent-derivation fallback anymore**.

---

## 3. API Key (LLM / Embedding)

- **Single source**: The Settings page UI. The system no longer reads `LLM_API_KEY` from `.env`, nor from any mounted secret.
- **Storage**: After being entered in the UI, it is encrypted with AES-256-GCM and written to `config.enc`, located in the `ragclaw_data` volume (`/app/data/config.enc`), and survives container rebuilds.
- **config.enc v1 format (byte layout)**:
  ```
  MAGIC(5) | version(1) | key_fingerprint(32) | nonce(12) | ciphertext
  MAGIC           = b"RAGC1"
  version         = 1 (uint8)
  key_fingerprint = sha256(KEK)[:32]
  nonce + ct      = AES-256-GCM output
  ```
  `key_fingerprint` embeds the KEK into the file as a fingerprint, so that "using the wrong key" can be detected **before** decryption.
- **Frontend capability boundary**: The frontend has no "manually fill in the secret file" entry point; the Settings page only has key input fields, plus the "Regenerate" buttons for `repl_auth_secret` / `jwt_secret`.

---

## 4. Other secrets (not in config.enc)

- **`repl_auth_secret`**: DB-backed. Auto-generated and persisted on first boot; UI rotation is authoritative and survives restarts; no longer sourced from a mounted file (scheme B).
- **`jwt_secret`**: DB-backed (same mechanism as repl_auth). The auth layer reads the `config_manager.jwt_secret` cache in real time, so rotation takes effect immediately without restart.
- **HTTPS cert / private key**: Stored in plaintext in the durable TLS volume (nginx must read it in plaintext), written by the backend; **not in config.enc**.

---

## 5. Operations contract (must read)

1. **You must back up two things separately**:
   - The `secrets/` directory (contains `ragclaw_config_key`) — the KEK.
   - The `ragclaw_data` volume (contains `config.enc` + sqlite) — the encrypted keys and all configuration.
   Neither is sufficient alone: **lose the KEK → `config.enc` cannot be decrypted (API Keys lost permanently); lose the volume → configuration and keys all lost.**

2. **Never replace `ragclaw_config_key` before re-entering the API Key**:
   The KEK is embedded into `config.enc` as a fingerprint; once they mismatch, the backend prints **FATAL "config.enc unreadable"** at startup and continues running with an **empty key** (**not** silently falling back to `.env` / defaults) until you re-enter it in the UI. During this period LLM calls fail, but **startup is not blocked**.

3. `ragclaw_config_key` **must be 64-char hex**; non-hex is rejected at startup.

4. **Production**: Use a strong random value, and absolutely never commit it to VCS (`secrets/` is already in `.gitignore`).

5. **k8s**: Map it as a native `Secret` and mount it at the same `/run/secrets/ragclaw_config_key` path — **no application code changes needed**.

## 6. Backup & Recovery

- **Backup example** (works whether stopped or online; the volume is file-level):
  ```bash
  # Back up the KEK
  cp -a secrets/ /path/to/backup/secrets-$(date +%F)/
  # Back up the data volume (includes config.enc + sqlite)
  docker run --rm -v ragclaw_data:/data -v /path/to/backup:/backup alpine \
    tar czf /backup/ragclaw_data-$(date +%F).tar.gz -C /data .
  ```
- **Recovery**: Put the KEK file back at `secrets/ragclaw_config_key`, restore the volume, and restart. **The premise is that the KEK and `config.enc` are paired** (i.e. they corresponded at backup time).
- **Lost KEK but volume still present**: `config.enc` cannot be decrypted → startup FATAL + empty key. The only recovery is to **re-enter the API Key via the UI** (it will be re-encrypted with the current KEK). The original key value cannot be recovered if it was not saved elsewhere.

---

## 7. Rotation

### 7.1 Rotating ragclaw_config_key (order matters)
1. **First**, re-enter the LLM / Embedding API Key in the Settings UI (re-encrypted with the **old** KEK, writing a new `config.enc`).
2. **Then** replace the mounted `ragclaw_config_key` file (generate new hex, update `secrets/` and the mount source).
3. Restart the backend. Now the new KEK pairs with the `config.enc` "re-entered under the new KEK", and the FATAL no longer appears.
- **Reversed order** (replace KEK first, re-enter later): A FATAL + empty key appears during startup; you must log into the UI to top up — the system still boots, only LLM is temporarily unavailable.

### 7.2 Rotating repl_auth_secret / jwt_secret
Simply click "Regenerate" in the Settings UI — **takes effect immediately, no restart needed** (the auth layer reads the `config_manager` cache in real time and invalidates the cache synchronously on rotation).

---

## 8. Migration

- **`config.enc` from before v1 (no `RAGC1` MAGIC) is universally rejected for decryption**. Admins must re-enter it via the UI; the system **does no transparent migration**.
- **The `.env` `LLM_API_KEY` default source has been removed**: First boot no longer reads `.env`; the API Key can only be set via the UI. Any historical `LLM_API_KEY` in `.env` is now ignored.

---

## 9. Security boundaries (Do NOT)

- Do not write `LLM_API_KEY` into `.env` (support has been removed; writing it has no effect).
- Do not commit `secrets/` into git.
- Do not manually edit `/run/secrets/ragclaw_config_key` or `config.enc`.
- Do not rely on "silent defaults" — any decryption failure will **loudly warn and run with an empty key**, forcing you to log into the UI to handle it, rather than quietly using the wrong key.
